# 0011: Ruru連携用MCPと配色JSONを静的配信に併設する

- ステータス: 採用
- 日付: 2026-09-18

## 決定

SSGとstatic assetsによるページ配信を維持し、配信用Workerを追加する。ADR 0002の「Workerスクリプトなし」という制約を置き換える。

Ruru連携はオーナー専用とする。認証は共通のBearerトークンのみとし、ユーザー管理やOAuthは導入しない。

`/mcp` は認証付きのステートレスなStreamable HTTPとして配色の取得と変更を提供する。配色はKVへ保存し、公開の `/theme.json` で色相と彩度の数値を返す。クライアントは有限数と範囲を検証してからCSS変数の値を組み立てる。両パスはWorker優先、その他はassets優先で配信する。配信用WorkerはSSG用SSRバンドルとは分離する。

取得した色相と彩度はlocalStorageへ保存し、復元時にも同じ数値検証を行い、次のページでは描画前に適用する。ページ遷移ごとの初期色からのアニメーションを防ぐため、保存色がある場合は表示中の配色を維持する。最新色は裏で取得して保存し、次のページから適用する。保存できない環境でも取得した数値を検証して配色を適用する。取得失敗時は503を返し、保存済みの配色を上書きしない。

作品コメントはRuruのMCPを開発エージェントが `ruru-work-comment` スキルで呼び出し、作品ディレクトリのJSONへ保存する。取得は手動で実行し、返答を確認してからコミットする。通常のビルドでは外部接続せず、保存済みコメントをHTMLへ埋め込む。

## 根拠

配色の変更を再デプロイなしで反映し、Ruruから汎用のMCPクライアントで操作できるようにする。通常のページ配信とビルドは自宅のRuruの稼働状況に依存させない。

配色は通常文字で4.5:1、選択・フォーカス表示で3:1以上のコントラストを保存前に検証する。sRGB色域外の設定は拒否し、ブラウザによる色域補正の違いを避ける。薄い装飾罫線には操作境界と同じ基準を適用しない。

## 影響

Worker実行、KV、MCP認証トークンの管理が必要になる。KVの地域間反映に遅延があるため、更新結果は即時に全地域で表示されるとは限らない。

CSS Modulesの3点セットと作品ページの通常遷移は維持する。NodeのテストはTypeScriptの直接実行を使うため、Node.js 24以上を使用する。
